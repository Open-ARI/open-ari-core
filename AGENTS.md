# Contributor instructions

- Read README.md and the relevant design documents before editing.
- No Apple ARI revision is supported until authoritative profiles and conformance evidence exist.
- Never make scaffold verification return verified or treat missing evidence as success.
- Keep Apple format, library, ABI, schema, policy, and trust-data versions separate.
- Keep core verification deterministic and offline. Bound attacker-controlled work.
- Use plain, factual writing. No em dashes or AI filler.
- Use the owner-approved logo. Do not generate or redesign artwork unless requested.
- Use Apache-2.0 SPDX headers and DCO sign-off. Run the relevant CI checks.
- Do not publish packages or claim audit coverage without the documented release gates.
